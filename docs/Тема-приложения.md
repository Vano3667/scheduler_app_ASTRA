# Как проверить исправление тёмной темы

Раньше у настроек планировщика и телефона был только один источник цвета: на светлом телефоне кнопки «Тёмная» не было. Теперь **тема** определяет светлый или тёмный интерфейс, а **стиль** определяет палитру и эффекты. Эти настройки независимы. После обновления со сборки № 11 сохраняется прежнее поведение по умолчанию («Как в системе»).

## Быстрая проверка на телефоне
1. На телефоне со светлой темой откройте шестерёнку на экране дня. Первая карточка настроек называется «Тема приложения». Если её нет, проверьте версию в разделе «О приложении» и обновите именно ASTRA поверх предыдущей версии (не удаляйте её).
2. Выберите «Тёмная». Экран настроек и экран дня должны стать тёмными сразу. Закройте и снова откройте планировщик — он должен остаться тёмным, даже если сам телефон светлый.
3. Переключите стиль «Обычный» ↔ «С эффектами». Тёмный фон должен сохраниться в обоих случаях. Проверьте подписи, календарь, редактор и график статистики.
4. Выберите «Как в системе». Переключение системной темы теперь должно менять тему приложения. Ручная «Светлая» должна оставаться светлой даже на тёмном телефоне.
5. Если размещён виджет, проверьте его заголовок, фон, строки и надпись для пустого дня в каждом режиме. Поддержка конкретного лаунчера проверяется отдельно.

## Автоматическая проверка
`smoke.yml` в GitHub Actions принимает `build_run` (ID успешной целевой сборки), `previous_run` (необязательно, например `46029500207` для № 11) и `check_theme=true`. Используется чистый эмулятор, не телефон пользователя. Сначала устанавливается предыдущий APK и создаётся тестовое дело. После обновления проверяется сохранность дела, затем — тема. Для проверки сравнивается яркость центральной области реальных кадров со светлой и тёмной палитрой, в том числе после перезапуска. Результат прогона — в шаге проверки темы; успешная компиляция сама по себе его не заменяет. Автотест не оценивает внешний вид всех экранов вручную.
